## 0. 项目定位

针对非公司制团体组织，基于"领导统筹分配"模式，做一款**纯前端（无后端服务器）**的轻量化排班工具。目标：
- 替代人工记忆，自动校验技能冲突、规避个人禁忌。
- 引入"劳累指数"与疲劳积分算法，实现**防透支、劳逸均衡**。
- 突发请假/离岗时，支持**临时一键替补**。
- 所有决策给出**可解释的理由**（为什么推荐 / 为什么阻止）。

| 弹窗 | 自建 openModal 组件（`src/ui/modal.js` 单点收口全部弹窗）：遮罩+白卡+header 右上角 X；**遮罩点击不关闭**，ESC / footer 可关；**打开时焦点落弹窗容器**（`tabindex=-1`，不聚焦按钮——防程序化 focus 触发 `:focus-visible` 键盘启发式点亮光晕并常驻；键盘可达性由 Tab 进入容器保底）；**弹窗栈**：嵌套弹窗 ESC 只关顶层；footer 惯例 = 次要钮（关闭/取消）在左、主按钮（保存/确认）在右（DOM 序 closeBtn 先、主按钮后）；破坏性操作一律经 `confirmDialog` 二次确认弹窗（左取消 + 右红「确认」，窄宽 `box-confirm` 400px） |

## 3. 核心数据结构

### 3.1 Project（任务/项目）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 唯一标识 | `"P101"` |
| `name` | String | 任务名称 | `"场地搬运"` |
| `fatigueScore` | Number | 劳累指数（1-3）：1=轻松，2=中等，3=高强度 | `3` |
| `requiredCapacity` | Number | 单班次所需人数 | `2` |
| `weekDays` | Array | **重复于星期几** [0-6]（0=周日）；**空数组 = 一次性任务**（不自动展开，由领导手动建班次） | `[0]`（周日） |
| `slots` | Array | **时段数组（至少一个）**（一个任务可有多个时段，每时段仅标签无时间） | `[{label:"自主安排"}]` / `[{label:"早"}]` |
| `active` | Boolean | 启停标记；`false` 时不自动展开班次 | `true` |
| `timeRange` | Object/null | **选填执行窗口** `{start,end}`（HH:mm，如 `{start:"08:00",end:"18:00"}`）；默认**仅展示**（配置卡/周历卡片小字）不参与算法；**例外：若某人员配置了每周时间安排（3.2 availability）且该人员被排到此任务，则此任务的 timeRange 参与该人员的可用性硬过滤**（见 4.2 第 12 条）；不填为 `null` | `null` |
| `description` | String | **选填任务说明**：描述任务情况/注意事项（自由文本，仅展示不参与算法）；Excel 模板/导入导出含该列；配置卡片限 2 行省略号折叠 + 点击展开 + hover 悬浮看全 | `""` |
| `bonusTags` | Array | **加分标签**（String[]，引用人员标签池文本）：凡带命中标签的人员排此任务按命中标签数累加加分（见 4.3）；仅任务编辑弹窗可选**已有人员标签**（同框只选不建，不自创）；不参与硬性过滤 | `[]` |

`slots[].label` 字段说明：**时段标签来自系统预置集合**：`自主安排 / 早 / 中 / 晚`（实现前可增删）。**任务至少配置一个时段**；任务级可选填 `timeRange` 执行窗口（仅展示、不参与算法，见 3.1），时段本身仍无具体时间。`自主安排` = 系统只排人不排时、由本人自主定时间；`早 / 中 / 晚` 仅作一天的组织标签（一人一时段至多一个任务，见 4.2）。

### 3.2 Staff（人员）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 唯一标识 | `"S001"` |
| `name` | String | 姓名 | `"张三"` |
| `allowedProjects` | Array | 可胜任项目 ID 列表 | `["P101","P102"]` |
| `preferredProjects` | Array | **擅长项目列表（带原因）** | `[{projectId:"P101", reason:"体力好，搬运熟练"}]` |
| `bannedProjects` | Array | **禁忌项目列表（带原因，硬性过滤）** | `[{projectId:"P103", reason:"腰伤，不宜搬重物"}]` |
| `maxWeeklyFatigue` | Number | 单周劳累积分上限（防透支；新人员默认 10，见 6） | `10` |
| `maxHeavyTaskCount` | Number | 单周高强度（3分）次数上限（新人员默认 2，见 6） | `2` |
| `maxMonthlyFatigue` | Number | 单月劳累积分上限（自然月固定窗口、非滚动；存量未配置随当前设置默认，见 6） | `40` |
| `maxMonthlyHeavyCount` | Number | 单月高强度（3分）次数上限（0 = 禁排高强度整个自然月；存量未配置随当前设置默认，见 6） | `8` |
| `status` | String | 人员状态机（见 3.3） | `"active"` |
| `joinedAt` | Number | 加入时间戳（ms），配置页卡片排序依据（新加入在前，已退出殿后） | `1785000000000` |
| `restFrom` | String/null | 休假前状态（`"new"`/`"active"`），开关恢复参与时还原；非休假状态为 `null` | `"active"` |
| `tags` | Array | **自由文本标签**（String[]，任意字符；同人同标签至多一个，由输入控件去重；用于人员分组/筛选，不参与算法） | `["组长","值班"]` |
| `availability` | Object/null | **每周时间安排（选填，硬性过滤）**：`null` = 不限制（存量/未配置同义）。对象 `{ mode, entries }`：`mode` = `"available"`（仅这些时段可排）/ `"unavailable"`（这些时段避开）；`entries[]` = `{ weekDays:[0-6 整数去重], start?:HH:mm, end?:HH:mm }`。**起止需同时填或不填**——不填 = 该星期整天；`end` 必须 > `start`，不跨日。同一天允许多条、一条可跨多个星期。任务有 `timeRange` 时段级判定；任务无 `timeRange`（如早/中/晚/自主安排）按「当天是否整天命中/是否设了时段」判定（见 4.2 第 13 条，设了局部可用时段时放行并黄字提醒）。卡片仅显示是否已配置；编辑弹窗全量编辑 | `null` |

### 3.3 Staff 状态机

```
new（新加入）→ active（活跃）→ left（退出，保留历史，永不参与）
                     ↕（开关可逆）
                  rest（休假）
```

| 状态 | 参与排班 | 均衡加分 | 高强度任务 | 历史保留 |
| --- | --- | --- | --- | --- |
| `new` | 参与 | **按团队平均计**（均衡加分为 0，不被驱动填坑） | **一票否决**（3分任务不参与） | 保留 |
| `active` | 参与 | 正常（`(团队平均 − 本人当前周积分) × 5`） | 受 `maxHeavyTaskCount` 约束 | 保留 |
| `rest` | **永不参与**（硬性过滤「休假中」） | 从团队平均中排除 | — | 保留 |
| `left` | 永不参与 | 从团队平均中排除 | — | 保留（历史/统计/导出仍含） |

- **转正**：领导在配置页手动将 `new` → `active`，解除新入保护。无自动转正。
- **休假**：配置页卡片开关直接切换（关=休假，开=恢复 `restFrom` 记录的休假前状态，`new` 休假恢复仍是 `new` 不自动转正）；休假是**长期状态**（区别于按天调整班次的「替换」功能，见 5.3）。
- **退出**：仅在配置页编辑弹窗的状态下拉中处理，状态机单向最终，不可逆（恢复需人工重新添加或编辑改回）。

### 3.4 Schedule（排班记录）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 排班记录 ID | `"SCH_001"` |
| `date` | String | 日期 `YYYY-MM-DD` | `"2026-08-30"` |
| `projectId` | String | 对应任务 ID | `"P101"` |
| `slotLabel` | String | 时段标签（引用 `Project.slots[].label`） | `"早"` |
| `staffIds` | Array | 已分配人员 ID 列表 | `["S001","S002"]` |

> **无 `status` 字段**：排班改即生效，无草案/确认两态。

## 4. 核心算法

### 4.1 展开（expand）

```
展开 = 仅「批量铺排」按钮触发（expandWeeks，幂等去重），或手动建班次。
周历渲染不再自动展开（ensureExpanded 已移除）——删除班次不会被自动复活；
新任务需批量铺排或手动建班次后才出现在周历。
铺排当前浏览范围（周 = 当前浏览周；月 = 浏览月覆盖的整段自然周）
        → 遍历范围内每个覆盖周的 active 项目 × 其 weekDays 命中日
        → 按项目每个 slot 生成班次（date + projectId + slotLabel + staffIds=[]）
一次性任务（weekDays=[]）不自动展开，领导手动建班次。
```

### 4.2 硬性过滤（filter，一票否决）

对候选人员，符合任一条件**严禁进入候选池**，并**返回被拒原因**：

1. `bannedProjects` 包含当前项目（含录入原因）。
2. 不具备 `allowedProjects` 权限。
3. **当日任务数超限**：该人员当天已排班次数 + 1 将超过 `dailyTaskLimit`（默认 2）。
4. **时段任务数超限**：该人员同一时段（自主安排/早/中/晚）已排班次数 + 1 将超过 `slotTaskLimit`（默认 1）。
5. 加入后**该班次所在自然周**内累计疲劳将超过 `maxWeeklyFatigue`（周窗口 = 班次日期归属的周一~周日，**滚动窗口**：过去的周已累计不影响本周判定，跨月周按各自日期归属各自周）。
6. 高强度项目（3分）且加入后该班次所在自然周内高强度次数将超过 `maxHeavyTaskCount`（同 5 的滚动周窗口）。
7. **休假中**：状态为 `rest`。
8. **已退出**：状态 `left`。
9. **新入保护**：状态 `new` 且该项目 `fatigueScore === 3`。
10. **月疲劳上限**：该人**班次所在自然月**（`YYYY-MM`，固定窗口非滚动）已累计疲劳 + 该项目 `fatigueScore` 将超过个人 `maxMonthlyFatigue`（未配置随设置 `defaultMonthlyFatigue`；文案三分同周上限「本月…已超限/已达上限/将超限」）。月初/月末相邻两天分属两月，存在月底卡死、月初重置的已知边界表现。
11. **月高强度次数上限**：该项目 `fatigueScore === 3` 且该人当月已排高强度次数 + 1 将超过个人 `maxMonthlyHeavyCount`（0 = 禁排高强度整个自然月；未配置随 `defaultMonthlyHeavyCount`；文案三分「本月高强度次数…」）。
12. **同一任务连任上限**（`tenureLimit` > 0 时）：同任务（合并计数，不分星期/时段）排班按自然周归并，本人连续占有期数（空窗不中断、他人接手中断；未来已排定计入段长）加入该班后 > `tenureLimit` → 拒绝，文案「同一任务将连任 N 期，超过连任上限 N 期，需轮换」。
    - **连任豁免**：若该班次扣除本人后无任何通过其余硬规则的候选（`splitEligible` 分池：`base` 空而 `tenured` 非空），连任拦截不成立 → 放行保运转（自动填充/替换推荐/分配弹窗候选一致）。
    - ctx 需带 `projectWeeks`（任务有发生周升序）+ `tenure`（各人各任务周占有计数）；`buildContext` 聚合、`cloneCtx` 深拷贝、`accumulateDelta` ± 同步；filter 读表 O(1) 判定（`core/tenure.js`）。
13. **每周时间安排冲突**（`staff.availability` 非 null 时）：以班次日期得星期，比对任务与该日规则。条目可不写起止（= 整天）。
    - **任务有 `timeRange`**：`available` 模式把当天可用段（含整天，整天 = `[00:00,24:00)`）合并后须完整覆盖任务，否则拒（文案「时间安排：任务 {start}–{end} 不在周X可用时间内」）；`unavailable` 模式与任一段（含整天）真实相交即拒（半开区间，端点相接不算；文案「时间安排：任务 {start}–{end} 与周X不可用时间重叠」）。
    - **任务无 `timeRange`**（早/中/晚/自主安排，不能确证具体落点）：按「整天/当天是否命中」判定——`unavailable` 当天有**全天不可用** → 拒（文案「时间安排：周X为整天不可用」），仅局部不可用段 → 放行（无从确证，不拦）；`available` 当天有**全天可用** → 放行，当天**只设了局部可用时段** → **放行 + 黄字提醒**（文案「时间安排：此人周X只在 {当日可用时段，如 09:00-12:00、14:00-17:00} 可排，而班次没写几点」，分配/替换候选黄字标出，不阻断点选），当天**完全未配可用时间** → 拒（文案「时间安排：周X未设可用时间，无法排未填具体时间的任务」）。
    - 人员未配置 → 本规则跳过（旧人员行为不变）。可用性拒绝与连任同时存在时 `tenureOnly=false`（不可豁免连任）。

### 4.3 打分（score）

对通过硬性过滤的候选：

$$Score = 擅长加分 + 标签加分 + 均衡加分$$

- **擅长加分**：该项目在 `preferredProjects` 中 → **+`preferredBonus`**（默认 15，配置页「设置」可调）。（附录入原因）。
- **标签加分**：当前任务 `bonusTags` 与该人员 `tags` 的交集 → **每命中一个标签 +`tagBonus`**（默认 15，配置页「设置」可调），多个命中累加（`|交集| × tagBonus`）。不区分人员状态（`new` 命中同样加，仅均衡恒 0）；`bonusTags` 来自人员标签池、命中即加分，无逐人原因。纯加分、不参与硬性过滤。
- **均衡加分**：`(团队窗口平均 − 该人员窗口积分) × balanceFactor`（系数默认 5，配置页「设置」可调）
  - **窗口积分** = **公平参考窗口**内该人员已排班次（含已分配的未来班次——计划即负荷）的 `fatigueScore` 之和。窗口 = **移动窗口**：终点 = 今天（决策日），起点 = 今天回看 `balanceWindowDays` 天（默认 30，系统设置可调，钳制 7~365）；未来班次 date ≥ 起点自然计入。
  - **窗口滑动语义**：旧账随时间滑出——某人某月被集中排班只影响随后约一个窗口期的均衡，窗口滑过后恢复公平竞争；窗口外历史数据照常存储与报表，仅不参与均衡。
  - **团队窗口平均** = 全部 `active` 状态人员的窗口积分平均值（**排除 `left` 与 `rest` 状态人员**；`new` 人员按团队平均取值参与计算，即其均衡加分为 0）。
  - **上限与均衡分工**：4.2 第 5、6 条按滚动自然周做「单周透支保护」；本条窗口积分是「近期公平标尺」（无界历史累计不进均衡）。展示口径的窗口化见 5.2 chip 语义与 5.4 疲劳分析。
（间隔保护扣分已随「具体时间」一并移除，负荷由 4.2 数量上限 + 周疲劳控制。）

### 4.4 智能排班（自动填充）

```
领导点击"智能排班"按钮（手动触发，不自动）：
1. 作用范围 = 当前浏览范围（与 4.1 批量铺排同构）：周 = 当前浏览周；月 = 浏览月覆盖的整段自然周（≤6，含首尾灰列邻月日），范围外班次一律不动；项目维度下仅当前任务（同范围约束）。
2. 排序：先按日期，同一天固定时段（早/中/晚）优先、自主安排最后（自主安排不占早/中/晚的时段名额，留到软约束捡漏；四时段名额各自独立计数，见 4.2 第 4 条）。
3. 预览 = 模拟执行（core/auto.js simulateAutoFill 纯函数）：按顺序逐个未满员班次多轮决策——硬性过滤 → 打分 → 分配得分最高者 → 记入 ctx 克隆（后续班次感知前面分配），全部内存完成、不写库；预览与实际执行共用同一决策通道（顺序/算法/输入一致），结果必然一致。
4. 确认后按预览结果一次批量落盘（store.saveSchedules 单次整表写），toast 汇报名额与达预警阈值人员。
执行入口：工具栏「智能排班」按钮（预览+确认弹窗，见 5.2）；卡片闪电 = 单班次快捷填充，直接执行不弹窗。
```

### 4.5 替补推荐（substitute）

```
领导点击人名 → 「替换」弹窗（按"人+某天"收集其当天全部班次，逐班次处理）：
1. 收集该人员当天全部班次。
2. 对每个班次：剔除该人员 → 硬性过滤（排除被替换人） → 打分 → **全量降序**（不截断）。
3. 弹窗逐班次将前 3 名作「推荐」、其余作「其他可选（默认折叠）」，均附人话推荐理由 + 二次确认一键替换。
替换只换班、不产生状态记录：被替换人当天其余班次照常，仍可被排入其他班次。
```

### 4.6 可解释性（Decision Reasoning）

算法返回**结构化原因**，而非仅结果：

- 过滤返回：`{ rejected: true, reasons: ["黑名单：腰伤，不宜搬重物", "本周疲劳将超限"] }`
- 打分返回：`{ staffId, score, breakdown: [{label:"擅长搬运+15", reason:"体力好"}, ...] }`
- 替补弹窗、智能排班、拖拽阻止，均展示原因明细。

```
[数据配置页] ➔ [周历网格看板] ➔ [智能排班/拖拽调整] ➔ [替换弹窗] ➔ [疲劳分析/导出]
```

### 5.1 数据配置页（config）
- 人员/任务均以**卡片网格**呈现（响应式多列，非表格）：头部=名称+状态徽标，字段行标签化；卡片网格装入**浅紫面板容器**（`.cfg-pane`，内容少时贴内容高度无滚动、内容超高时面板内滚动，滚动条收在面板内）。
- **名称实时筛选**（人员/任务 tab 头部，位于新增按钮左侧）：输入即按名称过滤隐藏不匹配卡片（不重建 DOM）；筛空显示「未找到」空态；数据本身为空时显示原「暂无」提示。
- **人员标签**：自由文本多标签（任意字符，同人同标签自动去重、互不重复——标签库全库共享，一人新建后他人即可复用）。人员卡片行区「可胜任 / 擅长 / 不合适」行之下加「标签」行（空显 `—`）；编辑弹窗标签字段 = **同框可输可选** chip 控件：聚焦即浮出已有标签候选（排除本表单已选，键入即时过滤，点选/↑↓+回车添加），输入文本无匹配时回车 = 自创为新标签，× 移除；旧人员无 `tags` 字段按空处理。
- **标签多选过滤**（仅人员 tab，名称搜索框右侧；与名称搜索叠加 = 与关系）：多选标签后只显示**同时带全部所选标签**的卡片，筛空空态文案列明条件；全库无人有标签时下拉不显示。排序按中文序。
- 人员卡片：**参与/休假开关**（关=休假 `rest` 并记录 `restFrom`，开=恢复原状态；`new` 休假恢复仍是 `new`），退出/转正在编辑弹窗的状态下拉处理；排序=已退出殿后、其余按 `joinedAt` 倒序（新加入在前）。
- 任务卡片：**启用/停用开关**即时切换 `active`；卡片 rows 含「加分标签」行（位于「时间段」行之下，标签 chip 展示，空显 `—`）。
- **任务加分标签**：任务编辑弹窗配「加分标签」= 从**全库已有人员标签池**中多选（标签来自人员 `tags`，复用 `tagsInput` 但 **`allowCreate:false` 只选不建**——聚焦浮出已有标签候选、点选/↑↓+回车添加、输入无匹配回车**不自创**）；凡带命中标签的人员排此任务时按命中标签数累加加分（见 4.3 标签加分）。命中理由副行（分配/替换弹窗候选）显示为 `加分标签[组长]`（多标签 `组长;值班` 分号并）。
- 底部操作区 = 开关 + 按钮组（**左「删除」右「编辑」**）。**删除语义**：仅用于零引用误建清理——人员出现在任一班次（`schedules[].staffIds`）、任务被排班记录（`projectId`）或人员配置（可胜任/擅长/不合适）引用时**禁止删除**，提示改用「退出」（保留历史）/「停用」（停止排班）；零引用经 `confirmDialog` 二次确认弹窗删除，删除即从本地库移除。
- 编辑弹窗（卡片「编辑」按钮）：编辑全部字段，含 `preferredProjects`/`bannedProjects` 的**原因录入**、`status` 状态管理（新入/活跃/休假/退出）。**字段 ⓘ 悬浮说明**：概念性字段（人员四上限/可胜任/擅长/不合适、任务劳累指数/所需人数）label 右侧带 ⓘ，hover/键盘聚焦浮出人话说明气泡（fixed 定位、滚动跟随），说明按字段语义通俗精简（≤ ~40 字）、禁算法术语；填 0 等特殊语义不特意说（fields.js `field()`/`rowsEditor()` 可选 `help` 参数挂文案，气泡挂 icon 内随表单回收）。
- **人员每周时间安排编辑**（编辑弹窗内字段组，位于「标签」之后、末尾）：规则说明统一收在 ⓘ help，页面不设单独空态文案；**默认展开一行空白时间段**（不填自动不生效）。行结构 = 星期多选下拉（周一~周日可多选）+ 开始/结束 `createTimePicker` + 删除，同星期可多行、一行可多星期（多对多）。**只勾星期、不写起止 = 该星期整天**；起止须同时填（`createTimePicker` 无跨日语义），保存时整组内联校验（未选星期/单边时间/倒挂/非法，红框定位），全空行在保存前过滤（整组空 = 不限制）。**模式 = 单选 seg「不可用时间 / 可用时间」**（不可用在前且为默认——符合「大多数人避开某些时段」的习惯；顶栏左，右侧为「添加时间段」）：**切换只换模式高亮、已填行保留不清空**（保存并重开才反映新模式；新建/空态默认展开一行空白）。人员卡片「标签」行下新增「时间安排」行：已配置 = tag `已配置(可用)` / `已配置(不可用)`（不展示具体时段），未配置 = `未设置`；**卡片空值统一用「未设置」占位（人员可胜任/擅长/不合适/标签、任务时间段/加分标签/任务说明同理，不再用 ——）**。
- 顶部分段 tab 三个：人员管理 / 任务管理 / **系统设置**（`config_tab` 记忆 `staff`/`project`/`settings`：页内操作重渲染与刷新后停留；侧栏菜单重新进入时清除，回默认「人员管理」）。
- **任务视图（任务管理 tab 就地切换）**：头部「任务视图」按钮进入纯展示态（head 换为「返回卡片 + 已启用计数 + 导出图片」，无任何管理操作）。清单条目三段式（屏幕与导出同构）：① 顶行 = 任务名（左）+ **右上角徽章**（灰紫小字，劳累指数火焰×n + N 人——劳累指数**只图标不配中文**）；② 时间行 = 时段 chip（按 `SLOT_LABELS` 序）· 频率（重复星期排序后「每周X、Y」；**7 天全勾缩写「每天」**；空 = 一次性任务省略）· 时间段（有值才显），片段间「·」；③ 说明全文（不折叠，保留换行，空显灰字占位）。不设图例行（🔥 含义不另行解释）。**停用任务不进入视图**（头部提示「已隐藏停用 N 项」）。「导出图片」将清单按 1200px 宽离屏白卡构图导出 PNG（标题「任务说明」+ 导出时间 + 共 N 项，文件名 `Tasks-任务说明图-日期.png`），与周历导出图同构。
- **系统设置 tab**：分组参数卡（班次数量上限 / 推荐打分 / 新建人员默认），每参数一行 = 名称 + 数字输入框 + 行内说明（含义与生效规则）；页底「系统怎么算」规则区（一票否决清单 / 打分公式 / 疲劳累计 / 预警时机，措辞同 docs/score-rules.md）。改动**暂存**，页尾「恢复默认」（只回填输入框不落盘）+「保存」（钳制 min、空值回系统默认后统一落盘，toast 提示）生效。
- Excel 模板导入 / 导出（人员、任务）。
- 一键导出全部数据为 JSON 备份。

### 5.2 排班视图（calendar，周/月双粒度）

- **粒度切换 = 工具栏 周/月 seg**（与维度 seg 并列）：周粒度 = 单周精细编排；月粒度 = 整月统筹（如按月轮值的任务整月排一次）。粒度记忆 `cal_scale`（刷新停留；侧栏菜单进入清除回周）。
- **周粒度（默认）**：单周面板 + 上周 / 今天 / 下周导航，周标签 `2026-08-31 ~ 09-06`。
- **月粒度**：以自然月为锚（标签 `2026-09`），渲染**覆盖该月的全部自然周面板纵向堆叠**（一个面板 = 一个完整自然周，最多 6 个，页面内纵向滚动浏览）；导航 = 上月 / 本月 / 下月。**首尾面板的非本月日期灰显**（日期灰 + 列淡底纹），该日班次照常显示与操作；面板间带周范围分隔（如「第 1 周 · 8/31~9/6」）。
- **周 ↔ 月切换回默认锚**（不沿用另一粒度的浏览位置，可预期）：周→月 = 本月；月→周 = 本周。粒度内导航「本周/本月」按钮（文案随粒度 = 本周/本月）跳当前粒度今天所在窗口。
- **面板内结构（周/月同构）**：
  - **行 = 预置时段标签（自主安排/早/中/晚），列 = 周一~周日**，行固定、不随项目动态增减，保证多项目对齐；**自主安排行置顶且高度较小（0.55fr）**，早/中/晚均分剩余；卡片不显示时间。
  - 单元格 = 该时段展开的班次卡片（任务名 + 已分配人名）。
  - 维度过滤（总览/项目/人员）在月粒度同样成立：项目 = 该任务整月各班；人员 = 该人整月排班（只读 + 「未排班」占位，可看整月空档）。
  - **人员维度标签过滤**（工具栏，仅「人员」维度激活时显示，位于人员下拉旁）：多选标签（与关系）后人员下拉候选仅含带全部所选标签者；记忆目标被过滤出候选时自动回退到过滤后首位；无匹配显示空态并提示清除标签；全库无标签时不显示。标签过滤为**页内临时态**（不持久记忆；切走维度或菜单重置即清）。
- **卡片人名 chip 口径随粒度**：
  - **周粒度**：红/黄按该浏览周累计判定（红 = 超 `maxWeeklyFatigue`/高强度上限；黄 = 达当日预警或接近上限），hover 显示「本周疲劳 X/Y · 高强度 H/M · 当日 N」。
  - **月粒度**：**不套周上限红黄**；红黄换绑**月上限**（月疲劳或月高强度超个人上限 = 红、≥ 0.8× 上限 = 黄；`tenureLimit` 连任不在此展示），hover 显示「本月累计 N/疲劳上限 · 本月高强度 H/上限 · 本周 X/Y · 当日 N」，人员维度月摘要「疲劳 F/上限 · 高强度 H/上限」。
  - 弹窗/摘要等计数口径：替换与分配弹窗打开于具体班次，计数恒为该班次所在自然周（周口径全粒度成立）；页面级维度摘要行随粒度（周 = 浏览周、月 = 浏览月）。
- **当日排班弹窗**：日期列头（周X + 日期格）hover 浮现日历钮（与建班次 ＋ 并排，人员只读维度无 ＋ 时贴右缘；月粒度灰显邻月日同样可进）→ 弹出**只读当日清单**（box-day 宽款 ~1040）：按预置时段序分组（**自主安排组置顶**，无班次时段不显示），组 = 实底圆珠时段 chip + 细线 + **班次卡横排成行**（卡片流自动换行，白卡描边；卡片层级 = 顶行任务名（17px 加粗）左侧 + 右侧**劳累指数火焰徽章**（浅橙圆底 🔥×劳累指数，只图标不配中文，title 劳累指数 N/3）+ meta 行「时间段（任务配了 `timeRange` 才显，`–` 连接，灰小字）· 已排人名（**深色加粗醒目**；无人在排时显灰字「暂未分配」）」+ 任务说明（**小字灰弱化**为次要信息，配了才显，保留换行））；**组内卡片按任务 `timeRange` 开始时间升序从左到右，未配时间者殿后（保持原数据序）**；口径跟随当前维度（总览 = 当天全部 / 项目 = 该任务 / 人员 = 该人）。footer 惯例左「关闭」+ 右「导出图片」（**当天无班次时空态文案 + 导出钮禁用**）；导出 = 任务说明图同构白卡（**1200 固定宽**，标题 `2026 年 9 月 8 日 · 周二` + 维度副题 + 导出时间，文件名 `Numbers-排班图-日-{总览|项目·名|人员·名}-{YYYY-MM-DD}.png`，名称清洗非法字符）。
- **手动建班次**：点击空白单元格 → 选择任务（默认列出一次性任务）→ 创建班次，用于临时/一次性任务；**已有班次的单元格底部有「+ 再建一个」按钮**（虚线圆钮，hover 高亮），可在同一时段追加多个班次。跨当前视图范围创建后自动跳转到该班次所在周/月。
- **批量铺排**：工具栏按钮 → 打开「预览 + 确认」弹窗，铺满**当前浏览范围**（周 = 当前浏览周单周；月 = 浏览月覆盖的整段自然周 ≤6，首尾含跨周邻月灰列，所见即所铺）——按范围内 active 项目 weekDays×slots 展开班次空壳（幂等去重、不分配人员），范围外不铺。弹窗实时预览「将新建 / 已存在跳过」按任务列明细；主按钮「开始铺排」确认后才写库，预计新建为 0 时禁用并提示原因（无周期任务 / 已全部铺好）。想铺更远 → 翻到目标周/月再点。
- **智能排班**：工具栏按钮 → 打开「预览 + 确认」弹窗，作用范围 = 当前浏览范围（同批量铺排，范围外不动；项目维度下仅当前任务）。**预览 = 模拟执行**（core `simulateAutoFill` 纯函数按既定顺序逐班次决策，不写库，与实际执行同一通道）：范围行（粒度 tag + 周/月范围 + 维度）→ 计数条「将填充 N 名额 · 需填班次 M 个 · K 个仍缺人」→ 按任务聚合明细行（填补班次·名额 / 仍缺 P 人）→ **缺口班次逐条单列**（周X · MM-DD + 时段 chip + 任务 + 仍缺人数——填不满即需人工收尾的清单）。主按钮「开始填充」确认后按预览结果**一次批量落盘**（toast 汇总实际名额 + 达预警阈值人员）；将填充为 0 时禁用并分因提示（无未满员班次 →「当前周/月无未满员班次」；有班次但零候选 → 原因提示受权限/上限/休假/疲劳等硬性约束限制）。卡片闪电（单班次自动填充）= 快捷路径，**不弹窗**，点即填 + toast。
- **弹窗候选过滤**（分配弹窗「可选人员」标题行、替换弹窗「替补候选」过滤栏，视图层收窄展示）：过滤栏 = **名称搜索输入**（常显，按姓名 includes 实时筛）+ **窄宽标签多选下拉**（全库有标签才显示），紧凑并排左置、双条件叠加为**与关系**——**算法硬性过滤与打分排序名单不变**。
  - **分配弹窗候选两区**：上区「可添加 N」按**推荐分降序**（scoreCandidate 擅长+均衡，stable 保原序），可添加行观感**学替换候选卡**（分徽章 + 周疲劳小字右置 + 人话「优选理由」副行，**仍点行即暂存加/取消**；分徽章 = 最高可加分紫高亮，随「可见且可点」动态转移——已选/置灰/被过滤不占位），下区「暂不可添加 N」**默认折叠**成 `▸ 暂不可添加 N`（点击展开，原因**单行省略**不折行、hover title 看全文）；区头计数随过滤联动、区空自隐，两区皆空显灰态空因文案。
  - **分配「点行即加 · 弹窗暂存 + 确认保存」**：点击可添加行 = 加入该人（无右侧常驻「＋ 添加」按钮），该行转**淡紫「已选」高亮**（信息位变 ✓ 已选），顶部「已排人员」chip 与进度条即时更新，候选区**不整窗重绘**（可连加多人）；**再点一次已选行 = 取消选中**（移除并回退高亮/进度，未满则其余置灰解除）；加到满员后其余未选行置灰 `no-slot` 禁点；顶部已排 chip 的 × = 移除（移除走整窗重绘，被移者重回候选）。**以上加/移均为弹窗内暂存**（只操作工作副本与克隆 ctx，不落库）；底部主钮「确认保存」（无改动时禁用）按**净差**（净增/净减人员）一次性写库并关窗，toast 汇总新增/移出人数；直接关闭/ESC = 放弃本次改动。**删除不在此弹窗**——班次删除统一走工具栏「批量删除」。
  - **替换弹窗过滤** = 当天全部班次组内候选按条件重滤（组内无匹配灰态提示）；过滤条件均为弹窗级临时态，关闭弹窗即弃。
- **拖拽人名**到其他班次：实时硬性校验，非法移动显示原因 + 红框警告并阻止。
- **未满员班次**显示闪电智能排班入口（点击为剩余名额自动填充，触发 4.4；已满员与人员只读维度不显示）。
- **批量删除班次**：工具栏「批量删除」按钮（**总览 / 项目维度**显示；人员只读维度不出现）→ 进入**多选态**：网格上方浮「批量删除 · 已选 N 个班次，点卡片勾选/取消」条，当前可见班次卡均可勾选（右上角勾选圆点随选中填充、选中高亮描边）；多选态下点卡 = 勾选/取消（**不开分配弹窗**，人名/闪电/拖拽均不触发）。「删除所选 (N)」（N=0 禁用）→ `confirmDialog` 二次确认（列 N 与前 ≤5 条预览）→ 确认后逐班次对其已排人员做**三轨 ctx 回退**（窗口/自然周/自然月 + 日/时段，同 accumulateDelta）再删除，toast「已删除 N 个班次」。多选范围 = 当前可见班次（周 = 当前周、月 = 整月各面板、总览 = 全部、项目 = 该任务）；**任何翻周/月、切粒度/维度、菜单重进等重渲染自动退出多选态**；空视图点入口提示「当前视图没有可删除的班次」。
- **导出**：排班视图只提供**「导出图片」按钮**（无下拉、无 Excel）——周粒度 = 当前周单面板；月粒度 = **整月长图**（按月视图完整周面板纵向堆叠导出，含周分隔条与首尾灰显邻月日；克隆时去除今日高亮/建班次/闪电等交互 UI）。文件名 `Numbers-排班图-{周|月}-{总览|项目·名|人员·名}-{周首|YYYY-MM}.png`（维度名称清洗非法字符）。
### 5.3 替换（calendar.js openReplaceDialog）

- 点击人名 → 一步直达**「人员替换」弹窗**（标题固定不含人名）：头部=姓名+状态徽标一行 + 副行「今日 N 个班次 · 周劳累积分 X/Y」（积分超个人上限时数字红字；积分口径 = 该班次日期所在自然周累计，与视图粒度无关）。
- 该人**当天全部班次分组**展示，组序**按时段行序排序**（自主安排/早/中/晚，同周历网格 SLOT_LABELS 序，同段保持原序）；组标题 = `周X · MM-DD` + 时段 chip + 任务名。
- 每组候选 = **推荐前 3（默认展开）** + **其他可选（第 4 名起按分序；默认折叠成「▸ 其他可选 N 人」行，点开列出）**。候选**卡**：主行=姓名 + 得分徽章（推荐首位 Top1 高亮）+「选此替补」常驻按钮，副行=**人话推荐理由**（规则见下）。算法层（`recommendSubstitutes`）返回**全部通过者按分降序、不截断**，推荐/其他分档是弹窗界面职责；**名称/标签过滤只在两区内各自筛**——推荐位恒为（无过滤全量）前 3，原第 4 名不上浮，被筛掉的推荐者不占位；折叠行展开态跨过滤重算保留（弹窗级 `moreOpen`，按班次 id）。
- **副行理由人话化**（不显示算式黑话与无单位裸数字）：擅长命中 → `擅长{任务}：{录入原因}`；本人窗口积分**低于**团队平均 → `近 N 天排班较少，建议优先`（N = 系统设置「公平参考窗口」天数，默认 30——时间范围具象化，不写「近期」虚词）；**高于**平均 → `近 N 天排班较多`；**≈平均齐平**（含新入均衡恒 0）→ **不产生均衡行**；无擅长且齐平 → 副行为空。不展示「本人 X/平均 Y」等无单位原始值（领导读不懂）。
- **「选此替补」须二次确认**：**触发点仅候选卡上「选此替补」按钮**（点行空白不触发，防误触），confirmDialog（标题「确认替换」，窄框多行文案）列明 `被替换人 现排于「周X · MM-DD · 时段 · 任务」，确认改为 顶替人？`，确认钮用**淡紫 btn-soft**（非破坏性变更，区别于删除类红 danger）；确认后**整窗关闭**（不留绿条/多余弹框）——替换即时落库 + toast + 周历刷新，需再换下一班重新点人名进入。取消则弹窗保持不动。
- 替换 = 一减一增：移除被替换人 + 加入替补，人数不变，ctx 计数双向同步；无候选组灰化提示「暂无可用替补人员」，不自动移除原人。
- **不产生任何状态记录**：被替换人当天其余班次照常参与、仍可被排入其他班次（无「当天空闲」硬约束；如需整天空闲由领导逐班次替换）。

### 5.4 疲劳分析（analysis）
- 全员**单指标**柱状图：仅展示累计劳累积分（黄渐变柱，高度=积分，同尺可比）横向对比；高强度次数不在本页展示（系统内仅排班分配弹窗可逐班次查看）。
- **时间窗口粒度 = 日 / 周 / 月**（工具栏 seg 切换）：窗口为自然日 / 自然周（周一~周日）/ 自然月，统计该窗口内班次累计积分。导航按粒度步进（日 ±1 天、周 ±7 天、月 ±1 月），窗口标签 日带「· 周X」、月为 `2026-09`。
- **跨粒度切换按窗口中心日换算**（日=当天、周=周四、月=15 号）保持阅读位置，不跳「今天」窗口；「返回当前」按钮文案随粒度动态 = 今天 / 本周 / 本月，点击跳当前粒度今天所在窗口。
- **周上限语义仅对周窗口成立**：超限判定（周积分 > 个人 `maxWeeklyFatigue` → 柱顶红色「超限」徽章 + 姓名红色加粗）、「疲劳超限」统计格只在周粒度出现；日/月窗口不判超限，仅展示数值（柱顶紫色积分）。日/月数值与周窗口无包含关系（跨月自然周的部分班次按各自窗口归属），口径以窗口标签为准。
- Y 轴整数刻度随数据自动扩展（默认 0-6 每格 1；有人超限自动扩至 8/10/12…，NICE 表驱动；超大数据回退整除取整）。
- 点击人员可下钻查看其得分构成/被拒原因。

### 5.5 导入导出
- Excel：仅人员/任务基础配置导入导出（班次不导入）；**排班结果不提供 xlsx 考勤导出**——排班存档走「导出图片」+ JSON 备份。人员模板/导出含「标签」列（`;` 分隔多标签；模板示例行带示例标签；旧模板无该列导入 = 标签留空）。**人员模板/导出另含「每周时间模式」（可用/不可用）与「每周时间段」两列**（时间段格式 `周一 全天;周三 09:00-12:00`，分号多条、`全天` 表示只选星期不写时间、星期用周一~周日全称）；旧文件缺这两列 = 更新保留原配置/新增不配置；两列填了但任一段非法（缺模式/缺段/星期错/跨日/倒挂）→ **整行跳过**并在结果里报条数，不静默放宽硬约束。任务模板/导出含「加分标签」列（`;` 分隔多标签，位于「任务说明」与「启用」之间）；**任务导入对加分标签只保留「导入时全库人员标签池」中已有文本**，不认识的丢弃并在消息里报丢弃数（旧模板无该列 = 留空，不整体中断）。
- JSON：全量备份 / 恢复——含业务三表（人员/任务/班次）+ **系统参数**（settings 单例对象，手动并入导出负载）；UI 状态（cal_view/cal_scale/config_tab/sidebar）属本机偏好**不进备份**。恢复时旧备份文件若无 `settings` 字段，保留导入方本机当前参数（向后兼容）；「重置」（resetAll，当前无 UI 入口、测试用）同清三表 + 系统参数 = 回全新默认。

## 6. 关键参数（可配置）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `dailyTaskLimit` | `2` | 一人一天任务数上限（达上限 +1 硬性拒绝） |
| `slotTaskLimit` | `1` | 一人一时段任务数上限（达上限 +1 硬性拒绝） |
| `warnDailyCount` | `1` | 预警阈值：当天任务数达该值 chip 变黄 + 排班 toast 提醒 |
| `preferredBonus` | `15` | 擅长加分 |
| `tagBonus` | `15` | 标签加分：命中任务加分标签的每个标签加的分（可多个累加） |
| `balanceFactor` | `5` | 均衡加分系数 |
| `balanceWindowDays` | `30` | 公平参考窗口（天）：均衡积分只参考「今天回看 N 天」的已排班次（含未来已分配），窗口外历史不进均衡（钳制 7~365） |
| `heavyFatigueThreshold` | `3` | 高强度判定阈值 |
| `defaultWeeklyFatigue` | `10` | 新人员默认周疲劳上限（设置可改；仅作用于新建人员与导入缺省，不改已有人） |
| `defaultHeavyTaskCount` | `2` | 新人员默认高强度次数上限（同上；0 = 禁排高强度） |
| `defaultMonthlyFatigue` | `40` | 新人员默认月疲劳上限（同上语义，自然月累计；存量未显式配置者随当前值） |
| `defaultMonthlyHeavyCount` | `8` | 新人员默认月高强度次数上限（同上；0 = 禁排高强度整个自然月） |
| `tenureLimit` | `3` | 同一任务连任上限（全局，0 = 关闭；允许连任 N 期，第 N+1 期强制轮换） |
