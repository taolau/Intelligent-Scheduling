# 团体组织轻量化智能排班系统 — 技术规范（spec.md）

> 本项目最高技术判定基准。所有实现必须与此对齐。
> 文档性质：**探讨版 PRD 对焦定稿**，2026-08-24 与 Tao 逐项对齐确认。

---

## 0. 项目定位

针对非公司制团体组织，基于"领导统筹分配"模式，做一款**纯前端（无后端服务器）**的轻量化排班工具。目标：
- 替代人工记忆，自动校验技能冲突、规避个人禁忌。
- 引入"劳累指数"与疲劳积分算法，实现**防透支、劳逸均衡**。
- 突发请假/离岗时，支持**临时一键替补**。
- 所有决策给出**可解释的理由**（为什么推荐 / 为什么阻止）。

## 1. 技术栈决策

| 项 | 决策 |
| --- | --- |
| 框架 | **无框架**，纯原生 ES Modules + 标准 Web API |
| 构建 | **开发多模块 + 发布单文件**：开发用 Vite dev server（模块化）；发布用 esbuild 打包为 `dist/index.html` 单文件，双击即用 |
| 外部依赖 | 仅 SheetJS（XLSX），用于 Excel 导入导出 |
| 存储 | localStorage（本地持久化） |
| 日历 | **不引入 FullCalendar**，自建周历网格视图（贴合"按星期几重复"场景） |
| 拖拽 | HTML5 Drag and Drop API |
| 图表 | 原生 `<canvas>` 自绘柱状图（疲劳分析） |
| 弹窗 | 原生 `<dialog>` |
| UI 样式 | **设计令牌 + 全局样式注入**：`src/ui/theme.js` 导出 `tokens` 并注入全局类（按钮五态/表单/弹窗/表格/toast/周历），视图挂 class 而非内联 cssText。内联样式无法表达 `:hover`/`:focus`/`:active`/`:disabled` 伪类，类体系是交互反馈的前提；样式随 JS 内联进单文件，build.js 不改 |

**架构分层**：算法层（`core/`）为**纯函数、无 DOM 依赖**，独立可测；视图层只负责展示与交互。

## 3. 核心数据结构

### 3.1 Project（任务/项目）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 唯一标识 | `"P101"` |
| `name` | String | 任务名称 | `"场地搬运"` |
| `fatigueScore` | Number | 劳累指数（1-3）：1=轻松，2=中等，3=高强度 | `3` |
| `requiredCapacity` | Number | 单班次所需人数 | `2` |
| `weekDays` | Array | **重复于星期几** [0-6]（0=周日）；**空数组 = 一次性任务**（不自动展开，由领导手动建班次） | `[0]`（周日） |
| `slots` | Array | **默认时段数组**（一个任务可有多个时段） | `[{label:"中午", startTime:"11:30", endTime:"13:00"}]` |
| `active` | Boolean | 启停标记；`false` 时不自动展开班次 | `true` |

`slots[].label` 字段说明：时段用**标签+时间范围（可配置）**表达。**时段标签来自系统预置集合**：`上午 / 中午 / 下午 / 晚上`（实现前可增删）。每个标签带默认起止时间，可在项目上修改。校验用真实时间，展示用标签。

### 3.2 Staff（人员）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 唯一标识 | `"S001"` |
| `name` | String | 姓名 | `"张三"` |
| `allowedProjects` | Array | 可胜任项目 ID 列表 | `["P101","P102"]` |
| `preferredProjects` | Array | **擅长项目列表（带原因）** | `[{projectId:"P101", reason:"体力好，搬运熟练"}]` |
| `bannedProjects` | Array | **禁忌项目列表（带原因，硬性过滤）** | `[{projectId:"P103", reason:"腰伤，不宜搬重物"}]` |
| `maxWeeklyFatigue` | Number | 单周劳累积分上限（防透支） | `6` |
| `maxHeavyTaskCount` | Number | 单周高强度（3分）次数上限 | `1` |
| `status` | String | 人员状态机（见 3.3） | `"active"` |

### 3.3 Staff 状态机

```
new（新加入）→ active（活跃）→ left（退出，保留历史，永不参与）
```

| 状态 | 参与排班 | 均衡加分 | 高强度任务 | 历史保留 |
| --- | --- | --- | --- | --- |
| `new` | 参与 | **按团队平均计**（均衡加分为 0，不被驱动填坑） | **一票否决**（3分任务不参与） | 保留 |
| `active` | 参与 | 正常（`(团队平均 − 本人当前周积分) × 5`） | 受 `maxHeavyTaskCount` 约束 | 保留 |
| `left` | 永不参与 | 从团队平均中排除 | — | 保留（历史/统计/导出仍含） |

- **转正**：领导在配置页手动将 `new` → `active`，解除新入保护。无自动转正。
- **请假不设独立状态**：通过 `Leave` 记录表达（见 3.5）。请一天假的 `active` 人员仍是 active，只是当天被硬性过滤排除；请假的临时性不影响状态机。

### 3.4 Schedule（排班记录）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 排班记录 ID | `"SCH_001"` |
| `date` | String | 日期 `YYYY-MM-DD` | `"2026-08-30"` |
| `projectId` | String | 对应任务 ID | `"P101"` |
| `slotLabel` | String | 时段标签（引用 `Project.slots[].label`） | `"中午"` |
| `staffIds` | Array | 已分配人员 ID 列表 | `["S001","S002"]` |

> **无 `status` 字段**：排班改即生效，无草案/确认两态。

### 3.5 Leave（请假记录）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 唯一标识 | `"LV_001"` |
| `staffId` | String | 请假人 ID | `"S001"` |
| `date` | String | 请假日期 `YYYY-MM-DD` | `"2026-08-30"` |
| `reason` | String | 原因（可选） | `"家中有事"` |

- 请假按"人 + 某天"记录，**连续多天 = 多条 `date` 记录**（不引入 dateRange，保持轻量）。
- 请假当天该人员视为不可参与（硬性过滤排除）。

## 4. 核心算法

### 4.1 展开（expand）

```
选中某周 → 遍历所有 active 项目 × 其 weekDays 命中该周的天
        → 按项目每个 slot 生成班次（date + projectId + slotLabel + staffIds=[]）
一次性任务（weekDays=[]）不自动展开，领导手动建班次。
```

### 4.2 硬性过滤（filter，一票否决）

对候选人员，符合任一条件**严禁进入候选池**，并**返回被拒原因**：

1. `bannedProjects` 包含当前项目（含录入原因）。
2. 不具备 `allowedProjects` 权限。
3. **时间段重叠**：该人员在该班次 `[startTime, endTime]` 内已有其他排班（按真实时间判断）。
4. 加入后本周累计疲劳将超过 `maxWeeklyFatigue`。
5. 高强度项目（3分）且加入后本周高强度次数将超过 `maxHeavyTaskCount`。
6. **请假中**：当日有 `Leave` 记录。
7. **已退出**：状态 `left`。
8. **新入保护**：状态 `new` 且该项目 `fatigueScore === 3`。

### 4.3 打分（score）

对通过硬性过滤的候选：

$$Score = 擅长加分 + 均衡加分 + 间隔保护扣分$$

- **擅长加分**：该项目在 `preferredProjects` 中 → **+15**（附录入原因）。
- **均衡加分**：`(团队平均周积分 − 该人员当前周积分) × 5`
  - **团队平均** = 全部 `active` 状态人员的周积分平均值（**排除 `left` 状态人员**；`new` 人员按团队平均取值参与计算，即其均衡加分为 0；请假不改变平均基数）。
  - 周积分 = 本周（周一~周日，**固定自然周**）该人员所有已排班次的 `fatigueScore` 之和。
- **间隔保护扣分**：距该人员**上次排班结束时间不足 `restHours`（默认 12 小时）** → **−10**。
  - 比 PRD 原"前一天扣分"更精确：同一自然日内午→晚班若间隔 <12h 也会扣分，符合实际作息。

### 4.4 智能排班（自动填充）

```
领导点击"智能排班"按钮（手动触发，不自动）：
1. 取当前周视图内所有空班次（staffIds=[]）。
2. 按班次时间先后排序（先早班后晚班）。
3. 逐个班次：硬性过滤 → 打分 → 分配得分最高者 → 立即更新该人周积分 → 下一班次。
   （逐个更新周积分，保证后续班次的均衡加分感知前面分配。）
```

### 4.5 替补推荐（substitute）

```
领导对某人某天标记请假（按"人+某天"整处理）：
1. 收集该人员当天全部班次。
2. 对每个班次：剔除该人员 → 硬性过滤（跳过请假人） → 打分 → 取 Top3。
3. 输出：弹窗逐班次展示 Top3 + 推荐理由 + 一键替换。
```

### 4.6 可解释性（Decision Reasoning）

算法返回**结构化原因**，而非仅结果：

- 过滤返回：`{ rejected: true, reasons: ["黑名单：腰伤，不宜搬重物", "本周疲劳将超限"] }`
- 打分返回：`{ staffId, score, breakdown: [{label:"擅长搬运+15", reason:"体力好"}, ...] }`
- 替补弹窗、智能排班、拖拽阻止，均展示原因明细。

## 5. 功能模块与 UI 交互

```
[基础配置页] ➔ [周历网格看板] ➔ [智能排班/拖拽调整] ➔ [请假替补弹窗] ➔ [疲劳分析/导出]
```

### 5.1 基础配置页（config）
- 人员表：表格内编辑全部字段，含 `preferredProjects`/`bannedProjects` 的**原因录入**、`status` 状态管理（转正、请假、退出）。
- 任务表：编辑项目、重复规则（星期几多选）、时段（标签+时间）。
- Excel 模板导入 / 导出（人员、任务）。
- 一键导出全部数据为 JSON 备份。

### 5.2 周历网格看板（calendar）
- **行 = 预置时段标签（上午/中午/下午/晚上），列 = 周一~周日**，行固定、不随项目动态增减，保证多项目对齐。
- 单元格 = 该时段展开的班次卡片（任务名 + 已分配人名）。
- **手动建班次**：点击空白单元格 → 选择任务（默认列出一次性任务）→ 创建班次，用于临时/一次性任务。
- **批量铺排**：工具栏按钮 → 弹窗输入 N（1-4）周 → 对接下来 N 周按 active 项目 weekDays+slots 展开班次空壳（幂等去重、不分配人员），用于提前计划。
- 周切换器查看任意周。
- **拖拽人名**到其他班次：实时硬性校验，非法移动显示原因 + 红框警告并阻止。
- 空班次显示"+ 智能排班"入口（触发 4.4）。

### 5.3 请假与替补（modal）
- 点击人名 → "标记请假" → 弹窗列出该人当天全部班次 → 逐班次 Top3 + 推荐理由 + 一键替换。
- 替换后原班次人员更新，请假人当日记录保留在 `Leave`。

### 5.4 疲劳分析（analysis）
- 本周全员柱状图：累计劳累积分 / 高强度次数双指标，横向对比。
- 超限人员红色标注；点击人员可下钻查看其得分构成/被拒原因。

### 5.5 导入导出
- Excel：仅人员/任务基础配置导入（班次不导入）；**排班结果可导出为 `.xlsx` 考勤表**（按周/月，含日期、任务、时段、人员）。
- JSON：全量备份 / 恢复。
