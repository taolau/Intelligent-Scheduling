## 0. 项目定位

针对非公司制团体组织，基于"领导统筹分配"模式，做一款**纯前端（无后端服务器）**的轻量化排班工具。目标：
- 替代人工记忆，自动校验技能冲突、规避个人禁忌。
- 引入"劳累指数"与疲劳积分算法，实现**防透支、劳逸均衡**。
- 突发请假/离岗时，支持**临时一键替补**。
- 所有决策给出**可解释的理由**（为什么推荐 / 为什么阻止）。

## 1. 技术栈决策

| 项 | 决策 |
| --- | --- |
| 框架 | **无框架**，纯原生 ES Modules + 标准 Web API |
| 构建 | **开发多模块 + 发布单文件**：开发用 Vite dev server（模块化）；发布用 esbuild 打包为 `dist/index.html` 单文件，双击即用 |
| 外部依赖 | SheetJS（XLSX，Excel 导入导出）+ html2canvas（周历导出图片，08-31 突破「仅 SheetJS」约束） |
| 存储 | localStorage（本地持久化）；db 层内存 Map 索引（O(1) CRUD、首次访问才从 localStorage 加载）；store 层增量缓存为唯一真源（视图经 getCache() 读、saveXxx 增量更新，loadAll 仅初始化/导入/重置）；**key 全量集中登记**于 `src/data/keys.js`（KEYS 常量 + STORES 表名，业务代码禁手写 `is_sched:` 字符串），台账见 `docs/storage.md` |
| 日历 | **不引入 FullCalendar**，自建周历网格视图（贴合"按星期几重复"场景） |
| 拖拽 | HTML5 Drag and Drop API |
| 图表 | 原生 `<canvas>` 自绘柱状图（疲劳分析） |
| 弹窗 | 自建 openModal 组件（`src/ui/modal.js` 单点收口全部弹窗）：遮罩+白卡+header 右上角 X；**遮罩点击不关闭**，ESC / footer 可关；**打开时焦点落弹窗容器**（`tabindex=-1`，不聚焦按钮——防程序化 focus 触发 `:focus-visible` 键盘启发式点亮光晕并常驻；键盘可达性由 Tab 进入容器保底）；**弹窗栈**：嵌套弹窗 ESC 只关顶层；footer 惯例 = 次要钮（关闭/取消）在左、主按钮（保存/确认）在右（DOM 序 closeBtn 先、主按钮后）；破坏性操作一律经 `confirmDialog` 二次确认弹窗（左取消 + 右红「确认」，窄宽 `box-confirm` 400px） |
| UI 样式 | **设计令牌 + 全局样式注入**：`src/ui/theme.js` 导出 `tokens` 并注入全局类（按钮五态/表单/弹窗/表格/toast/周历），视图挂 class 而非内联 cssText。内联样式无法表达 `:hover`/`:focus`/`:active`/`:disabled` 伪类，类体系是交互反馈的前提；样式随 JS 内联进单文件，build.js 不改 |

**架构分层**：算法层（`core/`）为**纯函数、无 DOM 依赖**，独立可测；视图层只负责展示与交互。

## 3. 核心数据结构

### 3.1 Project（任务/项目）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 唯一标识 | `"P101"` |
| `name` | String | 任务名称 | `"场地搬运"` |
| `fatigueScore` | Number | 劳累指数（1-3）：1=轻松，2=中等，3=高强度 | `3` |
| `requiredCapacity` | Number | 单班次所需人数 | `2` |
| `weekDays` | Array | **重复于星期几** [0-6]（0=周日）；**空数组 = 一次性任务**（不自动展开，由领导手动建班次） | `[0]`（周日） |
| `slots` | Array | **时段数组（至少一个）**（一个任务可有多个时段，每时段仅标签无时间） | `[{label:"自主安排"}]` / `[{label:"早"}]` |
| `active` | Boolean | 启停标记；`false` 时不自动展开班次 | `true` |
| `timeRange` | Object/null | **选填执行窗口** `{start,end}`（HH:mm，如 `{start:"08:00",end:"18:00"}`）；**仅展示**（配置卡/周历卡片小字），不参与 filter/score/expand，不做冲突检测；不填为 `null` | `null` |
| `description` | String | **选填任务说明**：描述任务情况/注意事项（自由文本，仅展示不参与算法）；Excel 模板/导入导出含该列；配置卡片限 2 行省略号折叠 + 点击展开 + hover 悬浮看全 | `""` |

`slots[].label` 字段说明：**时段标签来自系统预置集合**：`自主安排 / 早 / 中 / 晚`（实现前可增删）。**任务至少配置一个时段**；任务级可选填 `timeRange` 执行窗口（仅展示、不参与算法，见 3.1），时段本身仍无具体时间。`自主安排` = 系统只排人不排时、由本人自主定时间；`早 / 中 / 晚` 仅作一天的组织标签（一人一时段至多一个任务，见 4.2）。

### 3.2 Staff（人员）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 唯一标识 | `"S001"` |
| `name` | String | 姓名 | `"张三"` |
| `allowedProjects` | Array | 可胜任项目 ID 列表 | `["P101","P102"]` |
| `preferredProjects` | Array | **擅长项目列表（带原因）** | `[{projectId:"P101", reason:"体力好，搬运熟练"}]` |
| `bannedProjects` | Array | **禁忌项目列表（带原因，硬性过滤）** | `[{projectId:"P103", reason:"腰伤，不宜搬重物"}]` |
| `maxWeeklyFatigue` | Number | 单周劳累积分上限（防透支；新人员默认 10，见 6） | `10` |
| `maxHeavyTaskCount` | Number | 单周高强度（3分）次数上限（新人员默认 2，见 6） | `2` |
| `status` | String | 人员状态机（见 3.3） | `"active"` |
| `joinedAt` | Number | 加入时间戳（ms），配置页卡片排序依据（新加入在前，已退出殿后） | `1785000000000` |
| `restFrom` | String/null | 休假前状态（`"new"`/`"active"`），开关恢复参与时还原；非休假状态为 `null` | `"active"` |

### 3.3 Staff 状态机

```
new（新加入）→ active（活跃）→ left（退出，保留历史，永不参与）
                     ↕（开关可逆）
                  rest（休假）
```

| 状态 | 参与排班 | 均衡加分 | 高强度任务 | 历史保留 |
| --- | --- | --- | --- | --- |
| `new` | 参与 | **按团队平均计**（均衡加分为 0，不被驱动填坑） | **一票否决**（3分任务不参与） | 保留 |
| `active` | 参与 | 正常（`(团队平均 − 本人当前周积分) × 5`） | 受 `maxHeavyTaskCount` 约束 | 保留 |
| `rest` | **永不参与**（硬性过滤「休假中」） | 从团队平均中排除 | — | 保留 |
| `left` | 永不参与 | 从团队平均中排除 | — | 保留（历史/统计/导出仍含） |

- **转正**：领导在配置页手动将 `new` → `active`，解除新入保护。无自动转正。
- **休假**：配置页卡片开关直接切换（关=休假，开=恢复 `restFrom` 记录的休假前状态，`new` 休假恢复仍是 `new` 不自动转正）；休假是**长期状态**（区别于按天调整班次的「替换」功能，见 5.3）。
- **退出**：仅在配置页编辑弹窗的状态下拉中处理，状态机单向最终，不可逆（恢复需人工重新添加或编辑改回）。

### 3.4 Schedule（排班记录）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | String | 排班记录 ID | `"SCH_001"` |
| `date` | String | 日期 `YYYY-MM-DD` | `"2026-08-30"` |
| `projectId` | String | 对应任务 ID | `"P101"` |
| `slotLabel` | String | 时段标签（引用 `Project.slots[].label`） | `"早"` |
| `staffIds` | Array | 已分配人员 ID 列表 | `["S001","S002"]` |

> **无 `status` 字段**：排班改即生效，无草案/确认两态。

## 4. 核心算法

### 4.1 展开（expand）

```
展开 = 仅「批量铺排」按钮触发（expandWeeks，幂等去重），或手动建班次。
周历渲染不再自动展开（ensureExpanded 已移除）——删除班次不会被自动复活；
新任务需批量铺排或手动建班次后才出现在周历。
选中某周 → 遍历所有 active 项目 × 其 weekDays 命中该周的天
        → 按项目每个 slot 生成班次（date + projectId + slotLabel + staffIds=[]）
一次性任务（weekDays=[]）不自动展开，领导手动建班次。
```

### 4.2 硬性过滤（filter，一票否决）

对候选人员，符合任一条件**严禁进入候选池**，并**返回被拒原因**：

1. `bannedProjects` 包含当前项目（含录入原因）。
2. 不具备 `allowedProjects` 权限。
3. **当日任务数超限**：该人员当天已排班次数 + 1 将超过 `dailyTaskLimit`（默认 2）。
4. **时段任务数超限**：该人员同一时段（自主安排/早/中/晚）已排班次数 + 1 将超过 `slotTaskLimit`（默认 1）。
5. 加入后本周累计疲劳将超过 `maxWeeklyFatigue`。
6. 高强度项目（3分）且加入后本周高强度次数将超过 `maxHeavyTaskCount`。
7. **休假中**：状态为 `rest`。
8. **已退出**：状态 `left`。
9. **新入保护**：状态 `new` 且该项目 `fatigueScore === 3`。

### 4.3 打分（score）

对通过硬性过滤的候选：

$$Score = 擅长加分 + 均衡加分$$

- **擅长加分**：该项目在 `preferredProjects` 中 → **+`preferredBonus`**（默认 15，配置页「设置」可调）。（附录入原因）。
- **均衡加分**：`(团队平均周积分 − 该人员当前周积分) × balanceFactor`（系数默认 5，配置页「设置」可调）
  - **团队平均** = 全部 `active` 状态人员的周积分平均值（**排除 `left` 与 `rest` 状态人员**；`new` 人员按团队平均取值参与计算，即其均衡加分为 0）。
  - 周积分 = 本周（周一~周日，**固定自然周**）该人员所有已排班次的 `fatigueScore` 之和。
（间隔保护扣分已随「具体时间」一并移除，负荷由 4.2 数量上限 + 周疲劳控制。）

### 4.4 智能排班（自动填充）

```
领导点击"智能排班"按钮（手动触发，不自动）：
1. 取当前周视图内所有**未满员**班次（`staffIds.length < requiredCapacity`），缺几个补几个。
2. 排序：先按日期，同一天固定时段（早/中/晚）优先、自主安排最后（自主安排不占早/中/晚的时段名额，留到软约束捡漏；四时段名额各自独立计数，见 4.2 第 4 条）。
3. 逐个班次：硬性过滤 → 打分 → 分配得分最高者 → 立即更新该人周积分 → 下一班次。
   （逐个更新周积分，保证后续班次的均衡加分感知前面分配。）
```

### 4.5 替补推荐（substitute）

```
领导点击人名 → 「替换」弹窗（按"人+某天"收集其当天全部班次，逐班次处理）：
1. 收集该人员当天全部班次。
2. 对每个班次：剔除该人员 → 硬性过滤（排除被替换人） → 打分 → 取 Top3。
3. 输出：弹窗逐班次展示 Top3 + 推荐理由 + 一键替换。
替换只换班、不产生状态记录：被替换人当天其余班次照常，仍可被排入其他班次。
```

### 4.6 可解释性（Decision Reasoning）

算法返回**结构化原因**，而非仅结果：

- 过滤返回：`{ rejected: true, reasons: ["黑名单：腰伤，不宜搬重物", "本周疲劳将超限"] }`
- 打分返回：`{ staffId, score, breakdown: [{label:"擅长搬运+15", reason:"体力好"}, ...] }`
- 替补弹窗、智能排班、拖拽阻止，均展示原因明细。

## 5. 功能模块与 UI 交互

```
[数据配置页] ➔ [周历网格看板] ➔ [智能排班/拖拽调整] ➔ [替换弹窗] ➔ [疲劳分析/导出]
```

### 5.1 数据配置页（config）
- 人员/任务均以**卡片网格**呈现（响应式多列，非表格）：头部=名称+状态徽标，字段行标签化；卡片网格装入**浅紫面板容器**（`.cfg-pane`，内容少时贴内容高度无滚动、内容超高时面板内滚动，滚动条收在面板内）。
- **名称实时筛选**（人员/任务 tab 头部，位于新增按钮左侧）：输入即按名称过滤隐藏不匹配卡片（不重建 DOM）；筛空显示「未找到」空态；数据本身为空时显示原「暂无」提示。
- 人员卡片：**参与/休假开关**（关=休假 `rest` 并记录 `restFrom`，开=恢复原状态；`new` 休假恢复仍是 `new`），退出/转正在编辑弹窗的状态下拉处理；排序=已退出殿后、其余按 `joinedAt` 倒序（新加入在前）。
- 任务卡片：**启用/停用开关**即时切换 `active`。
- 底部操作区 = 开关 + 按钮组（**左「删除」右「编辑」**）。**删除语义**：仅用于零引用误建清理——人员出现在任一班次（`schedules[].staffIds`）、任务被排班记录（`projectId`）或人员配置（可胜任/擅长/不合适）引用时**禁止删除**，提示改用「退出」（保留历史）/「停用」（停止排班）；零引用经 `confirmDialog` 二次确认弹窗删除，删除即从本地库移除。
- 编辑弹窗（卡片「编辑」按钮）：编辑全部字段，含 `preferredProjects`/`bannedProjects` 的**原因录入**、`status` 状态管理（新入/活跃/休假/退出）。
- 顶部分段 tab 三个：人员管理 / 任务管理 / **系统设置**（`config_tab` 记忆 `staff`/`project`/`settings`，刷新停留）。
- **系统设置 tab**：分组参数卡（班次数量上限 / 推荐打分 / 新建人员默认），每参数一行 = 名称 + 数字输入框 + 行内说明（含义与生效规则）；页底「系统怎么算」规则区（一票否决清单 / 打分公式 / 疲劳累计 / 预警时机，措辞同 docs/score-rules.md）。改动**暂存**，页尾「恢复默认」（只回填输入框不落盘）+「保存」（钳制 min、空值回系统默认后统一落盘，toast 提示）生效。
- Excel 模板导入 / 导出（人员、任务）。
- 一键导出全部数据为 JSON 备份。

### 5.2 周历网格看板（calendar）
- **行 = 预置时段标签（自主安排/早/中/晚），列 = 周一~周日**，行固定、不随项目动态增减，保证多项目对齐；**自主安排行置顶且高度较小（0.55fr）**，早/中/晚均分剩余；卡片不显示时间。
- 单元格 = 该时段展开的班次卡片（任务名 + 已分配人名）。
- **手动建班次**：点击空白单元格 → 选择任务（默认列出一次性任务）→ 创建班次，用于临时/一次性任务；**已有班次的单元格底部有「+ 再建一个」按钮**（虚线圆钮，hover 高亮），可在同一时段追加多个班次。
- **批量铺排**：工具栏按钮 → 弹窗输入 N（1-4）周 → 对接下来 N 周按 active 项目 weekDays+slots 展开班次空壳（幂等去重、不分配人员），用于提前计划。
- 周切换器查看任意周。
- **拖拽人名**到其他班次：实时硬性校验，非法移动显示原因 + 红框警告并阻止。
- **未满员班次**显示闪电智能排班入口（点击为剩余名额自动填充，触发 4.4；已满员与人员只读维度不显示）。
### 5.3 替换（calendar.js openReplaceDialog）

- 点击人名 → 一步直达**「人员替换」弹窗**（标题固定不含人名）：头部=姓名+状态徽标一行 + 副行「今日 N 个班次 · 周劳累积分 X/Y」（积分超个人上限时数字红字）。
- 该人**当天全部班次分组**展示，组序**按时段行序排序**（自主安排/早/中/晚，同周历网格 SLOT_LABELS 序，同段保持原序）；组标题 = `周X · MM-DD` + 时段 chip + 任务名。
- 每组 Top3 候选**卡**：主行=姓名 + 得分徽章（Top1 高亮）+「选此替补」常驻按钮，副行=推荐理由（中性灰）；替换成功该组**折叠为绿条**「✓ 已由 X 替换」（组信息保留不占位），其余未完成组候选按新 ctx 重算。
- 替换 = 一减一增：移除被替换人 + 加入替补，人数不变，ctx 计数双向同步；无候选组灰化提示「暂无可用替补人员」，不自动移除原人。
- **不产生任何状态记录**：被替换人当天其余班次照常参与、仍可被排入其他班次（无「当天空闲」硬约束；如需整天空闲由领导逐班次替换）。

### 5.4 疲劳分析（analysis）
- 本周全员**单指标**柱状图：仅展示累计劳累积分（紫柱单柱，高度=积分，同尺可比）横向对比；高强度次数不在本页展示（系统内仅排班分配弹窗可逐班次查看）。
- Y 轴整数刻度随数据自动扩展（默认 0-6 每格 1；有人超限自动扩至 8/10/12…，NICE 表驱动）。
- 超限人员（周积分 > 个人 `maxWeeklyFatigue`）柱顶红色「超限」徽章 + 姓名红色加粗；点击人员可下钻查看其得分构成/被拒原因。

### 5.5 导入导出
- Excel：仅人员/任务基础配置导入（班次不导入）；**排班结果可导出为 `.xlsx` 考勤表**（按周/月，含日期、任务、时段、人员）。
- JSON：全量备份 / 恢复。

## 6. 关键参数（可配置）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `dailyTaskLimit` | `2` | 一人一天任务数上限（达上限 +1 硬性拒绝） |
| `slotTaskLimit` | `1` | 一人一时段任务数上限（达上限 +1 硬性拒绝） |
| `warnDailyCount` | `1` | 预警阈值：当天任务数达该值 chip 变黄 + 排班 toast 提醒 |
| `preferredBonus` | `15` | 擅长加分 |
| `balanceFactor` | `5` | 均衡加分系数 |
| `heavyFatigueThreshold` | `3` | 高强度判定阈值 |
| `defaultWeeklyFatigue` | `10` | 新人员默认周疲劳上限（设置可改；仅作用于新建人员与导入缺省，不改已有人） |
| `defaultHeavyTaskCount` | `2` | 新人员默认高强度次数上限（同上；0 = 禁排高强度） |
