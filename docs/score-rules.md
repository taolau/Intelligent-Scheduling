# 排班推荐分数规则

> 用途：给排班管理者的「为什么推荐他 / 为什么拒绝他」规则手册（人话版）。
> 本文档**实时反映当前版本的规则**：规则或参数变更时直接改正文与算例，不设历史记录区。
> 算法真源在 `.ai/spec.md` 4.1–4.4；改算法先改 spec，再同步本文的人话表述与算例。

---

## 1. 一句话概括

系统**从不随机推荐**：先过滤掉「绝对不能上」的人（硬性拒绝，一票否决），再给能上的人**打分排序**（擅长加分 + 标签加分 + 劳逸均衡加分），分数最高者 = 最该上的人。每次推荐都附带理由，理由中的每个数字都能在本文找到出处。

---

## 2. 名词（先看懂这些）

| 词 | 含义 | 出处 |
| --- | --- | --- |
| 劳累指数 | 每个任务的辛苦分，1 = 轻松、2 = 中等、**3 = 高强度** | 任务配置「劳累指数」 |
| 本周劳累积分 | 某**自然周**（周一 ~ 周日）该人**已排班次**劳累指数之和。只看这一周——上周干多少不影响这周，用来判断周疲劳上限 | 系统按排班自动累计 |
| 周疲劳上限 | 个人单周劳累积分上限（默认 10），超过即「超限」。按**该班次所在周**累计判断（滚动窗口） | 人员配置「周疲劳上限」 |
| 高强度次数 | 该班次所在周内排过的 3 分任务次数（默认单周上限 2 次，滚动窗口） | 人员配置 |
| 月疲劳上限 / 月高强度次数 | 个人单月劳累积分上限（默认 40）/ 单月 3 分任务次数上限（默认 8，填 0 = 整月不排高强度）。按**自然月**（固定、不滚动）累计；月初/月末相邻两天分属两月 | 人员配置「月疲劳上限 / 月高强度上限」 |
| 连任期数 | 同一任务**有排班的自然周**里连续排到同一人的期数；某周空窗不清零、换人接手才清零 | 系统按排班累计，用于「连任上限」 |
| 每周时间安排 | 某人在固定星期声明的**可用 / 不可用时段**（每行可只勾星期 = 整天，也可补几点到几点；同星期可多行） | 人员配置「每周时间安排」 |
| 窗口劳累积分 | **公平参考窗口**（默认今天回看 30 天）内该人已排班次的劳累指数之和，**已排定的未来班次也算**。窗口会滑动：旧账随时间滑出，某月被集中排班只影响随后约一个窗口期 | 系统按排班自动累计 |
| 团队窗口平均 | 所有「参与」状态人员窗口劳累积分的**平均值**（休假、退出者不计入） | 系统现算，作为横向比较的标尺 |
| 当日任务数 / 时段 | 一人一天至多几个任务（默认 3）；同一时段（早/中/晚/自主安排四段各自计数）至多 1 个任务 | 数据配置「系统设置」页 |

## 3. 硬性拒绝：命中任一即不推（一票否决）

对候选人员，命中任一条件即**严禁推荐**，并给出对应理由。按「本人 / 已排太多 / 时间轮换」归为三类，方便对号入座：

**① 本人不能排**
1. **禁忌项目**：该任务在该人员黑名单里（录入时附原因，如「腰伤，不宜搬重物」）。
2. **无胜任权限**：任务不在该人员「可胜任项目」里。
3. **休假中**：状态为休假者永不参与（硬性过滤「休假中」）。
4. **已退出**：永不参与，仅保留历史。
5. **新入保护**：状态为「新入」者不排 3 分高强度任务（转正后解除）。

**② 已经排太多**
6. **当日任务数会超上限**：今天已排 N 个，再加就超过「一天最多 3 个」。
7. **同时间段重复**：该时段（自主/早/中/晚）已排 1 个，一天一时段只排 1 个。
8. **本周积分会超周疲劳上限**：加上这个任务后，**该任务所在周**的积分 > 个人上限（防单周透支）。只看这一周会不会排太多，上周干得多不影响这周能不能排。
9. **高强度次数会超上限**：该任务所在周内 3 分任务已排满次数上限（同按滚动周）。
10. **月疲劳会超上限**：加这班后，**该班所在自然月**的劳累积分 > 个人「月疲劳上限」（自然月固定、不滚动）——与周上限分工：周防单周透支、月防整月堆积。相邻两天跨月会分别记进各自月。
11. **月高强度次数会超上限**：该自然月内 3 分任务已达「月高强度次数上限」；填 0 = 该人整月不排高强度。

**③ 时间或轮换冲突**
12. **连任到顶**：同一任务连续排满 N 期（N = 系统设置「同一任务连任上限」，默认 3，填 0 = 关闭）须轮换他人。某周空窗不清零、换人接手才清零；**仅当该班次剔除本人后无任何其他可排人选时，才破例放行保运转**。
13. **每周时间安排冲突**：该人在「每周时间安排」里声明了当天可用/不可用时段（可整天、可几点到几点），与任务对不上时拦下——
    - 任务**写了执行时段**：当天「可用时间」盖不住任务时段，或「不可用时间」与任务时段重叠 → 拦。
    - 任务**没写几点**（早/中/晚/自主安排，无从确证落点）：当天**整天不可用**、或「可用」当天**没设任何可用时段** → 拦；「可用」当天**只设了部分时段** → **放行 + 黄字提醒**该人当天仅有该时段可排（不阻断，因为班次没写几点）。未配置每周时间安排的人本规则不生效。

> **提示文案区分现状与预测**：被拒理由按当前状态措辞——「已超限」= 现在就已超上限；「已达上限」= 恰好排满；「将超限」= 现在还没超、加上这班才会超。看到 20/7 却提示「将超限」是不对的（已超应提示「已超限」）。

## 4. 打分：三个加分项

通过硬性过滤后，候选人按 **总分 = 擅长加分 + 标签加分 + 劳逸均衡加分** 从高到低排序（未命中的项不计）。

### 4.1 擅长加分：+15（默认，可在「系统设置」调整）

该任务命中此人「擅长项目」列表（配置时填写原因）→ 加 15 分，理由带出录入原因。

- 例：张三擅长搬运，录入原因「体力好」→ 张三排搬运 **+15**，理由显示「擅长搬运：体力好」。
- 让熟练的人优先上，且理由可追溯。
- 数值可在「系统设置」页调整：改大 = 更优先用熟练的人；改小 = 熟练优势变小。

### 4.2 加分标签：每命中一个 +15（默认，可在「系统设置」调整）

任务可配**加分标签**（在任务编辑弹窗「加分标签」里多选，选项来自全库人员已有标签）。排该任务的人员只要带命中标签 → **每命中一个 +15**、多个累加，理由带出命中标签名。

- 例：任务「值班」配了加分标签 `组长;有车`，两个标签都带的人排此任务 → **+30**。
- 纯加分，不拦人（没加标签不会不让排）；新入者命中同样加分。
- 数值可在「系统设置」页调整（默认 15）：调大 = 更优先用带指定标签的人。

### 4.3 劳逸均衡加分：（团队平均 − 本人）× 均衡系数（默认 ×10，可正可负）

```
均衡加分 = (团队窗口平均 − 本人窗口劳累积分) × 均衡系数
```

- **本人窗口积分 < 团队窗口平均** → 正分 → 靠前优先排（最近干得少的先上，拉平差距）。
- **本人窗口积分 > 团队窗口平均** → 负分 → 往后排（最近干得多的先歇）。
- **新入成员**：均衡加分为 0（视为「按团队平均计」）——不被算法反复拉去填坑，是否转正由领导手动决定。

**界面呈现（已人话化，替换弹窗候选副行不显示算式转述）**：旧版把每项加分拼成「擅长加分(15)：体力好；均衡加分(0)：团队平均 6，本人 6」这类黑话，普通人看不懂。现在副行只显示**判断句**：擅长命中 → `擅长{任务}：{录入原因}`；本人窗口积分**低于**平均 → `近 {N} 天排班较少，建议优先`；**高于**平均 → `近 {N} 天排班较多`。**N = 系统设置的「公平参考窗口」天数（默认 30，含今天）**——时间范围直接点明，不写「近期」这种虚词，也不甩「本人 X/平均 Y」这种无单位原始数字（领导看不懂 0 与 0.4 是什么分）。**本人 ≈ 平均（含新入）时不产生均衡行**——均衡为 0 无方向、无信息量，正是旧「均衡加分(0)」让人困惑的那行；无擅长且齐平的候选副行为空。想深究窗口怎么算、数字从哪来，看本手册 §4 公式与 §5 算例，界面不再展示原始值。

**为什么用「窗口」而不是「本周/本月/无界累计」：** 人多任务少时（如 45 人只排几十个班），单周/单月里大多数人根本没排过、积分同为 0，窗口内拉不开差距，算法只好反复选熟手。窗口（默认 30 天）留存近期账目——**一次预排下个月时，最近一个月谁干得多干得少都在账上，没被轮到的人自然被补偿**。同时窗口会滑动：起点（默认 30 天前）之外的旧账自动淡出，不会让某个人「某月被集中排班」变成永久负债（无界累计的毛病）。窗口天数可在「系统设置」调整。

**均衡系数是干什么的：** 它决定「防累」在推荐里有多大的话语权。系数小（如 1），擅长者哪怕窗口积分已比平均多 6 分（−6+15 分仍遥遥领先），算法基本总是选熟练的人——劳逸均衡名存实亡；系数大（如 10，默认），窗口积分高出平均 6 分的擅长者 = 15 − 60 = **负分**，会排到低积分的人后面，真的拦得住连续填坑。关键看 15 与系数的比值：系数 10 时，窗口积分高出平均 1.5 分的人，擅长红利就被扣光（15 ÷ 10）。**调大系数 = 更看重休息防透支；调小 = 更看重用熟练的人。** 数值可在「系统设置」页调整（默认 10）。

### 4.4 总分与排序

- 总分 = 三项之和（未命中的项不计，如没配加分标签则无标签分）。
- 智能排班逐个班次挑总分最高者；替换弹窗每组按分**全量降序**展示——推荐前 3 +「其他可选」（第 4 名起默认折叠），均附得分与理由；排完立即更新该人窗口积分，后续班次的均衡分「看得见」前面已排的结果——先上的低积分者被安排后，他在下一班次的得分自然下降，避免同一个人被反复填坑。

## 5. 算例（完整走一遍）

配置：搬运 = 劳累指数 3；张三窗口积分 4、李四 0、王五 2（三人均参与、均会搬运；数字即各自公平参考窗口内的积分）；团队窗口平均 = (4+0+2)/3 = **2**。要给未满员的搬运班次补 1 人。（以下按默认值：擅长 +15、均衡 ×10；若你在「系统设置」改过数值，按新值算。此处只算均衡项——例中任务没配加分标签、三人也没命中擅长（张三若擅长见表格备注），故主要看均衡分；「周疲劳上限」是否拦住看该任务所在周的单周累计，与窗口均衡互不影响。）

| 候选人 | 擅长加分 | 均衡加分 (2 − 本人)×10 | 总分 | 结果 |
| --- | --- | --- | --- | --- |
| 李四 | 0 | (2−0)×10 = +20 | **20** | ✅ 最高分，被推荐 |
| 王五 | 0 | (2−2)×10 = 0 | 0 | 与平均齐平 |
| 张三 | +15（若擅长） | (2−4)×10 = −20 | −5 | 窗口内干得多者即使擅长也被均衡分拉低（−5 < 20） |

界面里李四这一行不再显示算式转述「均衡加分(10)：团队平均 2，本人 0」，而是直接人话：**近 30 天排班较少，建议优先**（30 = 公平窗口默认天数；窗口怎么算、本人/平均数字从哪来见上文公式，界面不展示「本人 0/平均 2」这类无单位原始值）。若候选本人窗口积分 ≈ 平均（加 0 无方向）则不给均衡行。

## 6. 参数一览（哪些能调、哪些固定）

**可在「数据配置 → 系统设置」页调整（点「保存」后生效，推荐/替换/拖拽校验同步采用）：**

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| 每日任务数上限 | 3 | 一人一天最多任务数 |
| 每时段任务数上限 | 1 | 一人一时段最多任务数 |
| 当日预警阈值 | 2 | 当天任务数达该值时：排班卡片上的人名标签变淡黄 + 再排弹提示（不阻止） |
| 擅长加分 | 15 | 命中擅长项目时加的分数，越大越优先用熟练的人 |
| 标签加分 | 15 | 命中任务「加分标签」时每个标签加的分（可多个累加） |
| 均衡系数 | 10 | 按「团队平均 − 本人窗口积分」放大差距的倍数，越大越优先排窗口内干得少的人 |
| 公平参考窗口 | 30 天 | 均衡只参考「今天回看 N 天」的已排班次（含未来已排定）；越大 = 越久远的历史也参与公平比较，越小 = 只看近期（钳制 7~365 天） |
| 同一任务连任上限 | 3 | 同一任务连排满 N 期强制轮换，填 0 = 关闭；全班无人可替时才破例续排 |
| 月疲劳上限（新建默认） | 40 | 新人员单月劳累积分上限（自然月固定）；存量未单独设置者随当前值 |
| 月高强度上限（新建默认） | 8 | 新人员单月 3 分任务次数上限，填 0 = 整月不排高强度 |

**在人员/任务卡片可调：** 周疲劳上限（默认 10）、周高强度次数上限（默认 2）、**月疲劳上限（默认 40）、月高强度次数上限（默认 8）**、劳累指数；以及人员编辑弹窗里的**每周时间安排**（可用/不可用时段，见 §3-13）。

**固定不可调：** 高强度判定 = 劳累指数 3（代码写死，未来如需可做成设置项）。

## 7. 哪些操作在按这套规则跑

> 下表「过滤」都走 §3 的**全部**硬性规则（周/月上限、新入、连任、每周时间安排等），各入口口径一致——被 §3 拦下的同一个人，在任一入口都不会被推荐。

| 操作 | 过滤 | 打分排序 |
| --- | --- | --- |
| 智能排班（闪电） | ✅ 未满员班次逐班校验 | ✅ 取总分最高者，逐个分配并即时更新累计积分 |
| 替换弹窗（点人名） | ✅ 剔除被替换人后重算 | ✅ 全量排序，弹窗分「推荐前 3 + 其他可选（默认折叠）」+ 理由，选谁由你决定 |
| 拖拽人名 | ✅ 实时校验，非法移动红框阻止并显示理由 | ❌ 不排序，你拖谁就谁 |
| 手动分配弹窗（点空白格） | ✅ 候选列表逐个校验，被拒者灰化并显示理由 | ◐ 候选按推荐分从高到低排、最高分者紫高亮，但排谁由你点选（可跳过最高分者） |

## 8. 维护规则（重要）

1. 本文档与 spec 一样**只反映当前态**：规则变了就改正文与算例，**不设历史记录区**（历史见 git 提交信息）。
2. **算法真源是 `.ai/spec.md` 4.x**：先改 spec，再同步本文件的措辞、例子、数字；两边不一致时以 spec 为准。
3. 文档里的数字（15 / 5 / 6 / 2 / 1）都是**从代码核对来的事实**，动参数前先 grep `src/core/` 与 `DEFAULT_SETTINGS` 确认当前实现。
4. 界面若出现本文没解释的新理由词，先补本文再上线。
