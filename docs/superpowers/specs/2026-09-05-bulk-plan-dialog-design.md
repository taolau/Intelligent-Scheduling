# 批量铺排弹窗改造设计（铺当前浏览范围 + 预览确认）

> 2026-09-05 与 Tao 逐项确认。范围：批量铺排入口弹窗重做——范围语义收窄为「铺当前浏览范围」、UI 体例对齐、执行前预览与确认。

---

## 1. 背景与问题

现弹窗 `calendar.js bulkPlanDialog`（~1035）是内联手写样式（`style.cssText`）的简易表单：一句说明 + 「铺排周数 N（1-4，默认 2）」数字框 + 单按钮「开始铺排」，点击直接循环写库后 toast。

Tao 指出的问题：
- **UI/UX 粗糙**：未走项目 `field()`/chip 表单体例，无任何预览，点完才知道结果。
- **月粒度语义别扭**：导航按月走，弹窗却仍按「周」输数；且旧逻辑月视图下 N 上限 4 周，而覆盖整月的自然周可达 6 周——**当月根本铺不满整个浏览月**。
- **无确认**：点击即大批量写库，无兜底。

## 2. 语义决策（Tao 拍板）

1. **范围**：批量铺排 = **铺满当前浏览范围**（浏览周 = 当前 `currentWeekStart`；浏览月 = 当前 `monthAnchor`），去掉向后 N 周/月的滚动输入。
   - 周粒度 = 当前浏览这一周（单周）。
   - 月粒度 = 当前浏览月**覆盖的整段自然周**（所见即所铺，≤6 周，含首尾面板的灰显邻月日——灰列也会建空壳，与视图所见一致）。
   - 想铺更远 → 翻到目标周/月再点。
   - 措辞规避「本周/本月」：用户可能翻到过去/未来周月再铺，文案一律用「当前浏览周/月」语义 + 精确日期范围，不说真实「本周/本月」。
2. **确认形态**：**单层「预览 + 确认」弹窗**。工具栏单击打开弹窗，主按钮「开始铺排」才写库；不套独立二次 confirmDialog（铺排是新建空壳、幂等去重、非破坏，不该用红钮破坏语义）。
3. **架构**：预览逻辑抽成 **core 纯函数**（视图只渲染），见 §3。

## 3. 数据/算法层：`previewExpand`（`src/core/expand.js`）

```
previewExpand(projects, weekStarts, existingKeySet)
  → { totalNew, totalSkip, perTask: [{ projectId, weekDays, created, skipped }] }
```

- 复用 `expandProjectForWeek`（内部已拦「停用 / weekDays 为空」→ 返回空），对每个覆盖周逐行累加。
- 行 key = `日期|任务|时段`（与现弹窗去重同款）。`created` = 库中无该 key（将新建）；`skipped` = 已存在（自动跳过）。
- 该任务 created 且 skipped 均为 0（范围内不展开）→ 不进 `perTask`；仅 skipped>0（已全部存在）→ 仍列出，供展示「已铺满」。
- 纯函数、无 DOM，**node:test 可测**：一次性任务不铺 / 停用不铺 / 覆盖周去重计数 / 月粒度 5~6 周边界。

**覆盖周集合由视图统一推导**，同时喂给预览与执行（单一来源，不漂移）：
- 周 = `[currentWeekStart]`；月 = `weeksCovering(monthAnchor)`。

## 4. 视图/交互：重写 `bulkPlanDialog`（`calendar.js`）

周/月 × 总览/项目 四态一致（人员维度按钮本就不出现，不变）。

```
┌─ 批量铺排 ─────────────────────────────── × ┐
│ 铺排范围（周粒度）：2026-09-07 ~ 09-13 · 总览      │
│ 铺排范围（月粒度）：2026-09（8/31 ~ 10/4 覆盖周）· 项目·场地搬运 │
│ ┌─ 预览（超高内部滚动）──────────────────────┐ │
│ │  将新建  12 · 已存在跳过 3                  │ │   ← 计数条
│ │  任务名        新建/跳过     重复星期       │ │
│ │  场地搬运        6 / 1        周一、周三     │ │
│ │  门岗值班        4 / 2        周二~周五      │ │
│ │  巡园检查        2 / 0        周日           │ │
│ └───────────────────────────────────────────┘ │
│ 仅启用中的周期任务会铺排；空班次不分配人员；一次性任务请手动建班次 │
└───────────────────────────────────────────────┘
   [取消]                          [开始铺排]     ← totalNew=0 时禁用
```

- **范围标签**：周 = 粒度 tag + 「周一 ~ 周日」；月 = 粒度 tag + 月份 + 「首覆盖周周一 ~ 末覆盖周周日」，括注「含首尾跨周邻月日」（诚实反映灰列也建壳）。不用「本周/本月」字眼。
- **计数条**：主「将新建 N」强调；辅「已存在跳过 M」。**N=0 时禁用主按钮**并按原因区分提示：
  - `perTask` 为空 → 「该范围无启用中的周期任务（一次性任务请手动建班次）」。
  - 有任务但全 skipped → 「范围内周期班次已全部铺好」。
- **执行**：确认 → `expandWeeks(scopeProjects, weekStarts[0], weekStarts.length, createSchedule)` 逐行去重写库（新建数与预览 `totalNew` 应一致）→ toast「已铺排当前{周|月} · 新建 N · 跳过 M」→ 重渲染，停留当前浏览位置。
- **体例对齐**：去掉全部手写 inline cssText；弹窗内容布局（预览行/计数条/表头）收敛进 `theme.js` 新增 `.bulk-*` 样式段；chip/按钮复用现有类。

## 5. 边界与空态

| 情形 | 处理 |
| --- | --- |
| 项目维度且该任务为一次性任务 / 停用 | 预览空 → 禁用 + 提示手动建班次 |
| 总览下无任何启用中的周期任务 | 同上 |
| 范围内已全部铺好 | perTask 有、totalNew=0 → 禁用 + 「已全部铺好」 |
| 月粒度覆盖周含邻月灰列 | 照常建壳（与视图灰列一致），范围标签注明 |
