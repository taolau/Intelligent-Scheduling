# 团体组织轻量化智能排班系统需求文档 (PRD)

## 1. 项目背景与目标

针对非公司制团体组织，基于“领导统筹分配”模式，设计一款纯前端（无后端服务器）的轻量化排班工具。系统旨在**替代人工记忆**，通过自动校验技能冲突、规避个人禁忌，并引入“劳累指数”算法，实现**防止个人透支、劳逸均衡**及**突发临时一键调配**。

---

## 2. 系统架构与技术栈要求

* **架构模式**：纯前端运行（Pure Frontend），所有计算与数据处理在浏览器端完成。
* **数据存储**：优先使用 `IndexedDB` 或 `LocalStorage` 存储本地数据，支持 JSON / Excel 格式的一键导入与导出备份。
* **推荐技术栈**：Vue 3 / React + Tailwind CSS / Element Plus + FullCalendar（或自定义日历组件）+ SheetJS (XLSX)。

---

## 4. 核心逻辑与算法规则

### 4.1 硬性限制（一票否决）

在生成预排班或搜索替换人员时，符合以下任一条件的人员**严禁加入候选池**：

1. 该人员在 `bannedProjects`（黑名单）中包含当前项目。
2. 该人员不具备 `allowedProjects`（可胜任）权限。
3. 该时间段内该人员已有其他排班任务（时间重叠）。
4. 加入当前项目后，该人员本周累计 `fatigueScore` 将超过 `maxWeeklyFatigue`。
5. 该项目为高强度任务（3分），且加入后该人员本周高强度任务次数超过 `maxHeavyTaskCount`。

### 4.2 打分推荐机制（匹配度与均衡度计算）

对通过硬性限制的候选人，按下式计算匹配得分：


$$Score = (擅长加分) + (负荷均衡加分) - (连续加班扣分)$$

* **擅长加分**：属于 `preferredProjects`，加 **15 分**。
* **负荷均衡加分**：`(团队平均周积分 - 该人员当前周积分) × 5`（积分越少，得分越高）。
* **间隔保护扣分**：前一天已有排班任务，扣 **10 分**。

### 4.3 临时变更与替补推荐算法

当针对某一已排班次点击“申请替补”时：

1. **自动剔除**：根据 4.1 硬性限制过滤所有人员。
2. **打分排序**：根据 4.2 计算所有可用人员得分。
3. **输出**：在弹窗中展示得分最高的 **Top 3 最佳替补**，并附带推荐理由（如：“技能最擅长且本周劳累积分最低”）。

## 5. 功能模块与 UI 交互需求

```
[基础配置页] ➔ [日历/甘特图看板] ➔ [一键自动排班/拖拽调整] ➔ [紧急替补弹窗] ➔ [疲劳度分析/Excel导出]

```

1. **基础数据管理模块**：支持表格化录入/修改人员评估表与项目表，提供 Excel 模版导入功能。
2. **周期预排班看板**：以日历/甘特图展示全月班次。点击“智能一键填充”调用算法生成草案；支持鼠标拖拽人名微调，拖动时实时校验规则（冲突显示红框警告）。
3. **紧急调配响应模块**：在看板点击具体人员可标记“请假/离岗”，系统弹出“替补推荐弹窗”，展示 Top 3 候选人并支持一键替换。
4. **负荷统计与导出**：以柱状图展示全员累计劳累积分与高强度任务次数，支持一键导出排班结果为 `.xlsx` 考勤表。
