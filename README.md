# Numbers · 团体轻量化智能排班

面向**非公司制团体组织**（志愿者团队、兴趣社团、值班小组等）的**纯前端**排班工具。不做复杂的工时核算，只专注「领导统筹分配」这一件事——排谁、为什么不排谁、怎么防透支，每一步都说得清理由。

- **双击即用**：无后端、无安装、无账号。下载单个 `Numbers.html` 双击打开即可，数据保存在本机浏览器（localStorage），可随时导出 JSON 备份。
- **一票否决 + 人话理由**：技能不符、个人禁忌、周/月上限、休假……不满足条件的候选人直接不进候选池，并写明被拒原因。
- **防透支**：劳累指数（1-3）+ 周/月双窗口上限 + 高强度次数限制，配合「公平参考窗口」均衡打分，避免同一个人被反复排。
- **批量与临时兼顾**：周期任务一键铺排、智能排班一键填充；突发请假按「天」替换，给出前 3 名替补与推荐理由。

## 功能一览

| 模块 | 说明 |
| --- | --- |
| 数据配置 | 人员 / 任务的卡片式增删改；Excel 模板导入导出；可胜任·擅长·不合适三列表（带原因）；标签；每周时间安排（可用 / 不可用时段） |
| 排班视图 | 周 / 月双粒度网格（行 = 自主安排·早·中·晚，列 = 周一~周日），总览 / 项目 / 人员三种维度 |
| 智能排班 | 预览即模拟执行（与实际落盘走同一决策通道），确认后一次批量写入 |
| 替换 | 点人名进入当天班次分组，候选全量降序、前 3 名作推荐并附人话理由，二次确认后即时生效 |
| 疲劳分析 | 日 / 周 / 月三种窗口柱状图，周窗口带个人上限超限判定 |
| 导出 | 排班图 / 任务说明图（PNG）、人员 / 任务 Excel、全量 JSON 备份 |

## 快速开始

### 直接使用（推荐）

到 [Releases](https://github.com/taolau/Intelligent-Scheduling/releases) 下载 `Numbers.html`，**双击打开**即可（Chrome / Edge 等现代浏览器）。数据只存在本机，建议定期用「导出 JSON 备份」留档。

> 注：单个 HTML 内已打包全部代码与样式，不需要联网、不需要起服务器。

### 本地开发

```bash
npm install
npm run dev     # Vite 开发服务器（多模块）
npm test        # 算法层单元测试（node:test）
npm run build   # 打包为 dist/Numbers.html 单文件
```

## 目录结构

```
src/
  data/    数据层：模型定义与校验、localStorage 封装（keys / db / store）
  core/    算法层（纯函数、无 DOM）：展开 / 硬性过滤 / 打分 / 替补推荐 / 连任判定 / 自动填充
  views/   视图层：排班日历（周·月双粒度）、数据配置、疲劳分析
  ui/      通用组件：弹窗 / 下拉 / 时间选择器 / 标签输入 / Excel / 导出图 / toast
test/      算法层与数据层单元测试
docs/      规则手册与台账（score-rules 打分规则人话版、storage 存储 key 台账、测试数据播种脚本）
.ai/       项目规范与记忆（spec.md 为技术规范终稿）
```

## 规则与算法

- **硬性过滤（一票否决）**：禁忌项目、可胜任范围、当日 / 时段任务数上限、周 / 月疲劳上限、周 / 月高强度次数、休假 / 已退出 / 新入保护、同一任务连任上限、每周时间安排冲突——每条拒绝都带具体原因。
- **推荐打分**：`得分 = 擅长加分 + 标签加分 + 均衡加分`。均衡加分以「公平参考窗口」（默认近 30 天，可调）内本人积分与团队平均的差值计算，窗口外历史不参与均衡。
- **可解释**：算法返回结构化原因，界面直接展示「为什么推荐 / 为什么阻止」，拒绝理由区分「已超限 / 已达上限 / 将超限」。

细则见 [`docs/score-rules.md`](docs/score-rules.md)（人话版）与 [`.ai/spec.md`](.ai/spec.md)（技术规范，一切实现的判定准则）。

## 技术栈

原生 ES Modules + 标准 Web API，**无框架**；开发用 Vite，发布用 esbuild 打包为单文件；Excel 读写用 xlsx-js-style，图片导出用 html2canvas；疲劳分析图表为原生 canvas 自绘。
